## Hedef

Projeyi test/demo durumundan çıkarıp yayınlanabilir bir MVP çalışma düzenine taşıyacağım:

- `C:\Users\PC\Desktop\Alevi\server\index.js` üzerinden `node index.js` ile başlayan sunucu.
- Siyah-beyaz/monokrom tema seçeneği.
- Ana Keşfet sayfasında aktif kullanıcılar şeridi.
- Düşük kaynak tüketimli tek üretim sunucusu varsayılanı.
- İkinci sunucu için otomatik peer heartbeat/mesh bağlantısı; ancak ortak veritabanı olmadan iki aktif yazma node’u açılmayacak, böylece split-brain ve veri kaybı riski oluşmayacak.
- Kullanıcının açık yetkisiyle iki uzak panel sunucusundaki mevcut Jarvis proje dosyalarını yedekleyip çalışma alanını Alevi server dosyalarıyla değiştirme.

## Önemli mimari kararı

Uzak panel sunucularında PostgreSQL/Redis/Docker servisi doğrulanmış değil; ikisi de Node.js 22 ve yaklaşık 1 GB RAM ile çalışıyor. Mevcut Prisma/PostgreSQL API’sini bu ortama eksik bağımlılıklarla kopyalamak yayınlanabilir bir kurulum olmaz.

Bu nedenle `server/index.js`, Node.js 22’nin built-in SQLite desteğiyle çalışan düşük kaynaklı üretim adapter’ı olacak:

- Kalıcı SQLite dosyası: `server/data/alevi.sqlite`
- Şifreli hassas profil alanları: AES-256-GCM
- Parolalar: scrypt
- Tokenlar: imzalı kısa ömürlü bearer token
- Rate limit ve güvenli response header’ları
- Auth, profil, keşfet, like/pass, eşleşme, mesaj, topluluk ve health endpoint’leri
- Presence: TTL’li aktif kullanıcı heartbeat’i
- Dosya izinleri ve secret’lar `.env`/panel environment üzerinden

Mevcut `services/api` + Prisma mimarisi korunacak ve geliştirme/kurumsal deployment için kaynak gerçekliği olarak kalacak. `server/` ise iki panel sunucusunda ek bağımlılık gerektirmeyen yayın runtime’ı olacak. Böylece `node index.js` doğrudan çalışır ve uzak makinede `npm install`/PostgreSQL zorunluluğu olmaz.

İki node için:

- **Primary:** SQLite yazma ve kullanıcı trafiği.
- **Secondary:** Aynı runtime + mTLS/heartbeat peer izleme; varsayılan olarak standby/read-only.
- Peer bağlantısı otomatik heartbeat ve reconnect ile kurulacak.
- SQLite dosyası iki node arasında körlemesine kopyalanmayacak; bu, veri bozulması doğurur.
- Gerçek active-active HA istenirse sonraki aşamada ortak PostgreSQL/Redis veya managed DB gerekir.

## API ve aktif kullanıcılar

Standalone server’da şu endpoint’ler olacak:

- `GET /health/live`
- `GET /health/ready`
- `GET /health/mesh`
- `POST /v1/auth/register`
- `POST /v1/auth/login`
- `GET/PATCH /v1/profile/me`
- `GET /v1/discover`
- `POST /v1/presence/heartbeat`
- `GET /v1/presence/active`
- `POST /v1/matches/swipe`
- `GET /v1/matches`
- `GET/POST /v1/community/posts`
- `GET/POST /v1/messages`
- Güvenlik için block/report endpoint’leri

Presence için istemci heartbeat’i TTL ile güncellenecek; ana sayfa yalnızca son kısa süre içinde heartbeat gönderen ve görünürlük izni olan kullanıcıları gösterecek. Hassas dini/kültürel bilgiler hiçbir aktif kullanıcı sorgusunda dönmeyecek.

## Flutter yayın istemcisi

1. `AppConfig` varsayılanı mock/test modundan çıkarılacak; release build gerçek API URL’sini `--dart-define=API_BASE_URL=...` ile zorunlu alacak.
2. Login sonucu access token secure storage’a yazılacak; `ApiClient` isteklerine `Authorization: Bearer` eklenecek.
3. `ActiveUser` modeli ve mock fixture eklenecek.
4. `DiscoverScreen` içine mevcut `AvatarCircle` bileşenini kullanan “Şu anda aktif” yatay şerit eklenecek.
5. Loading/empty/error durumları eklenecek; API erişilemezse kullanıcıya gerçek hata gösterilecek, sahte çevrimiçi sayısı gösterilmeyecek.
6. Mevcut bordo/krem tema korunacak ve ikinci seçenek olarak siyah-beyaz/monokrom tema eklenecek.
7. Profil ayarlarında tema seçici: `Sıcak`, `Monokrom`, `Sistem`.
8. Hard-coded ana renkler `ColorScheme`/tema extension üzerinden okunacak; kart, buton, avatar online noktası ve navigation bileşenleri monokrom temada gerçekten siyah-beyaz görünecek.
9. Debug/mock badge ve test metinleri release ekranından kaldırılacak.
10. Flutter testleri güncellenecek; `flutter analyze`, `flutter test` ve Android release build çalıştırılacak.

Release APK/AAB için gerçek Android keystore yoksa pipeline açıkça imzasız/mağaza-dışı durumu bildirecek; debug imzası release diye adlandırılmayacak. Kullanılabilir test APK’sı ayrıca `debug` adıyla tutulacak.

## İki uzak sunucuda yayınlama

Kullanıcının önceki açık yetkisine dayanarak şu sıra uygulanacak:

1. Her iki panel node’unda `/home/container` içindeki eski Jarvis çalışma alanı tarihli yedek olarak paketlenecek.
2. Yalnız uygulama çalışma dosyaları temizlenecek; sistem/hosting dosyalarına dokunulmayacak.
3. `/home/container/server` klasörü oluşturulacak.
4. `server/index.js`, `.env.example`, README ve gerekli runtime dosyaları panel dosya yükleme veya panel terminalindeki doğrulanmış aktarım yöntemiyle yüklenecek.
5. Her node’da Node 22 ile `node index.js` çalıştırılacak.
6. İlk node primary, ikinci node standby olarak yapılandırılacak.
7. Peer host/port, node id, join secret ve TLS sertifikaları secret olarak panel environment’a yazılacak; private key dosyaları loglanmayacak.
8. Panel port yönetiminden API portu yalnız gerektiği kadar açılacak; public kullanımda HTTPS reverse proxy/domain zorunlu tutulacak.
9. `GET /health/live`, `/health/ready`, `/health/mesh` ve bir kayıt/giriş smoke test’i ile doğrulama yapılacak.
10. Startup ayarı şu biçime getirilecek:

```bash
cd /home/container/server && node index.js
```

Mevcut Jarvis projesi silme işlemi geri döndürülemez olduğu için önce yedek alınacak ve yalnızca yeni dosyaların checksum/health doğrulaması sonrası çalışma alanı değiştirilecek.

## Kabul ölçütleri

- Temiz bir `server` klasöründe `node index.js` sunucuyu başlatır.
- `/health/live` 200 döner ve node id gösterir.
- İki node yapılandırıldığında `/health/mesh` peer durumunu ve heartbeat’i gösterir.
- Kayıt/giriş ve SQLite kalıcılığı process yeniden başladıktan sonra korunur.
- Aktif kullanıcılar yalnız gerçek heartbeat sonrası ana sayfada görünür.
- Monokrom tema tüm ana ekranlarda uygulanır ve tema seçimi kalıcıdır.
- Flutter release analiz/testleri temizdir; release artifact adı debug ile karıştırılmaz.
- Uzak panel startup komutu `cd /home/container/server && node index.js` olur.
- Jarvis dosyaları aktif dizinden çıkarılmış olur; kurtarma yedeği ayrı ve açıkça isimlendirilmiş olur.
